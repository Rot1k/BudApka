# Інструкції для AI-асистентів

Перед зміною продуктового сценарію прочитай [`README.md`](README.md), а перед написанням або форматуванням C# — [`CODE_STYLE.md`](CODE_STYLE.md) та [`.editorconfig`](.editorconfig). Ці файли описують межі навчального прототипу й командні домовленості.

- Вважай план лабораторної роботи №3 та прямо погоджені командою рішення джерелом актуального scope. Якщо зміна суперечить їм, не вигадуй нову вимогу: поясни конфлікт і запропонуй варіант.
- Не представляй демо-профілі, ціни, заявки, відгуки чи повідомлення як справжні дані. Не вигадуй респондентів, інтерв’ю або цитати.
- Зберігай основні продуктові обмеження: клієнт сам вибирає майстра; точна адреса відкривається лише обраному майстру; паспорт обладнання добровільний; жодних оплат, ескроу, реальної SMS-автентифікації чи автопризначення.
- Дотримуйся помірної MVVM-архітектури з `CODE_STYLE.md`. Не додавай пакети чи шари без конкретної потреби, не переписуй весь прототип за один крок.
- Тримай рядки коду близько 100 символів і перенось довгі виклики та ініціалізатори; не залишай горизонтально прокручуваних рядків.
- Для UI змін надавай перевагу окремому XAML View для відповідного сценарію та ViewModel для його стану/команд. Залишай code-behind для UI-специфічної поведінки.
- Не редагуй згенеровані каталоги `bin/` і `obj/`, якщо завдання прямо цього не вимагає.
- Не форматуй без запиту весь репозиторій. Якщо редагуєш уже щільно записаний файл, форматуй лише потрібну область або узгоджений набір файлів.
- Після змін коротко повідомляй, що змінено, які перевірки виконано та що лишилося демо/не реалізованим.
